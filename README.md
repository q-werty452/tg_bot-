# Telegram-бот с ИИ (Claude / GPT / Gemini)

Бот-мост между тобой и большой языковой моделью. Умеет переключаться
между Claude (Anthropic), GPT (OpenAI) и Gemini (Google) и отвечать
в двух режимах.

---

## Запуск за 5 шагов

### 1. Получить токен бота

Открой в Telegram [@BotFather](https://t.me/BotFather) → `/newbot` → придумай имя
и username (должен заканчиваться на `bot`). BotFather пришлёт токен вида
`123456789:AAH...` — это и есть `TELEGRAM_BOT_TOKEN`.

### 2. Получить ключ ИИ (хотя бы один)

- **Gemini:** https://aistudio.google.com/apikey → Create API key. Есть бесплатный лимит.
- **Claude:** https://console.anthropic.com → API Keys → Create Key. Нужен пополненный баланс.
- **GPT:** https://platform.openai.com/api-keys → Create new secret key. Тоже нужен баланс.

Ключ показывают **один раз** — сразу скопируй.

Ключи легко перепутать, они отличаются началом строки:

| Провайдер | Начало ключа | Переменная в .env    |
|-----------|--------------|----------------------|
| Anthropic | `sk-ant-`    | `ANTHROPIC_API_KEY`  |
| OpenAI    | `sk-proj-` / `sk-` | `OPENAI_API_KEY` |
| Google    | `AIza`       | `GOOGLE_API_KEY`     |

### 3. Установить зависимости

Открой терминал в папке проекта и выполни:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Первая строка создаёт виртуальное окружение — отдельную «песочницу» с
библиотеками только для этого проекта, чтобы не засорять систему.
Вторая — включает её (в начале строки терминала появится `(.venv)`).

> **Почему `py`, а не `python`.** На твоём компьютере команда `python`
> перехвачена заглушкой Microsoft Store и ничего не делает. Настоящий
> Python 3.13.3 установлен и вызывается через `py` — это стандартный
> лаунчер Python для Windows. Внутри активированного `.venv` заработает
> и `python` тоже.

> Если PowerShell ругается на запуск скриптов, выполни один раз:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

### 4. Создать файл .env

Скопируй `.env.example` в `.env` и впиши свои значения:

```powershell
Copy-Item .env.example .env
notepad .env
```

Минимум, что нужно заполнить: `TELEGRAM_BOT_TOKEN` и один из ключей ИИ.

### 5. Запустить

```powershell
python bot.py
```

В консоли появится `Бот запущен: @твой_бот`. Открой его в Telegram и напиши `/start`.
Остановить — `Ctrl + C`.

При следующем запуске шаги 1–4 повторять не нужно, достаточно:
`.\.venv\Scripts\Activate.ps1` и `python bot.py`.

## Панель управления (CRM)

К боту прилагается веб-панель — отдельный репозиторий
[tg-bot_srm](https://github.com/q-werty452/tg-bot_srm). Туда попадают все
обращения жителей: переписка, фотографии, темы, статусы. Оттуда же сотрудники
мэрии отвечают людям и настраивают самого бота — тексты ответов, ключи моделей,
готовые ответы, рассылки.

**Это две отдельные программы, запускать надо обе** — каждую в своём терминале:

```bash
cd ~/tg-bot_srm && ./venv/bin/python manage.py runserver   # панель
cd ~/tg_bot-    && .venv/bin/python bot.py                 # бот
```

Панель откроется на `http://127.0.0.1:8000`.

Без панели бот не пропадёт: он продолжает отвечать жителям, а обращения
складывает в файл `crm_queue.jsonl` и дошлёт, когда панель включат. Обратное
тоже верно — панель работает без бота, просто новых обращений в ней не будет.
Порядок запуска роли не играет.

**Как они связаны.** Всего двумя строками в этом `.env`:

```
CRM_URL=http://127.0.0.1:8000
CRM_BOT_TOKEN=<значение BOT_API_TOKEN из .env панели>
```

Токен должен совпадать в обоих файлах символ в символ. Если оставить
`CRM_URL` пустым, бот работает автономно, как раньше.

**Что появляется у бота, когда панель подключена:**

- каждое сообщение и фотография попадают в карточку обращения;
- ИИ определяет тему заявки и подставляет категорию, адрес и район;
- сотрудник может перехватить разговор — тогда бот молчит, а отвечает человек;
- под ответами появляются кнопки «Помогло / Не помогло»;
- тексты ответов, справочник контактов и выбор модели берутся из панели,
  править файлы на сервере больше не нужно;
- бот рассылает объявления жителям по команде из панели.

Полная инструкция по установке панели, связке, переносу ключей в веб-интерфейс,
работе карты обращений и разбору неполадок — в README репозитория
[tg-bot_srm](https://github.com/q-werty452/tg-bot_srm).

| Команда   | Что делает                                    |
|-----------|-----------------------------------------------|
| `/start`  | Приветствие и краткая справка                 |
| `/help`   | Подробно про режимы                           |
| `/mode`   | Переключить режим ответа                      |
| `/model`  | Переключить Claude / GPT / Gemini              |

## Два режима ответа

**▤ Развёрнутый** — полный структурированный ответ: объяснение, примеры,
нюансы. Модели разрешено «подумать» перед ответом (у Claude это
`thinking: adaptive`, у Gemini — поведение по умолчанию).
Лимит ответа: 8000 токенов.

**◇ Обсуждение** — короткие реплики на 1–3 предложения, встречные вопросы
и комментарии, как в обычной переписке. Размышления сведены к минимуму
(нужна скорость), лимит ответа урезан до 500 токенов — это вторая страховка
от простыней помимо промпта.

Пример разницы на одном и том же вопросе «Что такое переменная?»:
развёрнутый режим выдал 2714 символов со структурой и примерами,
диалоговый — 230 символов и встречный вопрос «Хочешь пример на каком-нибудь
языке программирования?».

Режим — это связка «системный промпт + лимит токенов + настройки модели».
Всё лежит в `prompts.py`, менять характер бота можно там, не трогая логику.

## Что за файлы в проекте

```
tg_bot-/
├── bot.py                       ← точка входа, вся логика Telegram
├── config.py                    ← настройки и ключи
├── prompts.py                   ← тексты промптов для двух режимов
├── storage.py                   ← память бота (кто что выбрал + история)
├── icons.py                     ← набор иконок + чистка эмодзи из ответов ИИ
├── utils.py                     ← мелкие помощники (нарезка длинных текстов)
├── crm.py                       ← связь с панелью управления
├── remote_config.py             ← настройки, приходящие из панели
├── classify.py                  ← определение темы обращения через ИИ
├── selftest.py                  ← самопроверка: 153 теста без ключей и сети
├── providers/                   ← слой работы с ИИ
│   ├── __init__.py              ← фабрика: выдаёт нужного провайдера по имени
│   ├── base.py                  ← общий контракт для всех провайдеров
│   ├── claude.py                ← реализация для Anthropic
│   ├── openai_provider.py       ← реализация для OpenAI
│   └── gemini.py                ← реализация для Google
├── requirements.txt             ← список библиотек
├── .env.example                 ← шаблон файла с секретами
└── .env                         ← твои реальные ключи (создаёшь сам, в git не кладём!)
```

Файлы, которые появляются сами и в git не попадают: `bot.log` (логи),
`crm_queue.jsonl` (недоставленные в панель обращения), `crm_config_cache.json`
(последняя конфигурация с панели), `incoming_media/` (фото от жителей).

### bot.py
Главный файл. Здесь `Dispatcher` — маршрутизатор aiogram: он смотрит на входящее
сообщение и решает, какая функция его обработает. Функции помечены декораторами
`@dp.message(...)` и `@dp.callback_query(...)`. Тут же: клавиатуры с кнопками,
индикатор «печатает…», обработка ошибок и запуск polling'а.

### config.py
Читает `.env` и складывает всё в один объект `settings`. Сразу проверяет, что
токен есть и что задан хотя бы один ключ ИИ — иначе бот падает с понятным
сообщением при старте, а не посреди работы. Смысл файла: секреты и настройки
в одном месте, а не разбросаны по коду.

### prompts.py
Системные промпты — инструкции модели «как себя вести». Пользователь их не
видит, но они влияют на каждый ответ. Именно здесь живёт разница между двумя
режимами. Хочешь другой характер бота — правишь только этот файл.

### storage.py
Ни Telegram, ни API моделей не хранят состояние: каждое сообщение приходит
само по себе, а историю переписки нужно присылать модели заново при каждом
запросе. Здесь для каждого чата хранятся выбранный провайдер, режим и история.
История обрезается до последних N сообщений (`HISTORY_LIMIT`) — длинная история
означает больше токенов, то есть дороже и медленнее.

**Важно:** хранение в оперативной памяти. Перезапустил бота — всё забылось.
Когда понадобится постоянная память (и выгрузка обращений в CRM), меняешь
только этот файл на SQLite/Postgres, остальной код не трогаешь.
Сессии, в которых 12 часов ничего не происходило, выгружаются из памяти
автоматически (`Storage.cleanup`), чтобы бот не разрастался за месяцы работы.

### providers/
Слой абстракции. Боту всё равно, с кем он разговаривает: он вызывает
`provider.ask(...)` и получает текст. Как устроен конкретный API — забота
конкретного класса.

- `base.py` — абстрактный класс с методом `ask()`. Задаёт «контракт»:
  любой провайдер обязан его реализовать.
- `claude.py` / `openai_provider.py` / `gemini.py` — реализации. Полезно
  открыть их рядом: три разных API решают одну задачу по-разному.
- `__init__.py` — фабрика `get_provider("claude")` + кэш созданных клиентов.

Чем отличаются три API — сравнительная таблица:

| | Системный промпт | Роль ответа модели | Где текст ответа |
|---|---|---|---|
| Anthropic | отдельный параметр `system` | `assistant` | список блоков `content` |
| OpenAI | первое сообщение в `messages` | `assistant` | `choices[0].message.content` |
| Google | `config.system_instruction` | `model` | `response.text` |

Провайдер Gemini добавлялся уже после того, как бот был написан, — и `bot.py`
при этом не менялся вообще. Понадобился новый файл `gemini.py` плюс одна строка
в реестре `__init__.py`. Вот ради чего нужен базовый класс: новый ИИ
подключается, не задевая логику бота.

### icons.py
Внешний вид бота. Здесь два блока.

**Реестр иконок.** Код бота пишет `ICONS.error`, а не конкретный символ, —
поэтому сменить оформление всего бота можно правкой одного файла. Иконки
заданы текстовыми символами Unicode, которые рисуются тонкой контурной линией
**в цвет текста**, а не цветными «блобами» системного шрифта: `✓ ✕ ⚠︎ ℹ︎ → ▸ ↺ ◎`.
Выглядят одинаково в светлой и тёмной теме и не зависят от того, Android
у пользователя или iPhone.

Отдельная деталь — селектор начертания `U+FE0E` (VS-15). Некоторые символы
шрифт умеет рисовать двумя способами: как текст или как цветное эмодзи.
VS-15 означает «рисуй как текст». Обратный ему `U+FE0F` (VS-16) — «рисуй
цветным»; именно его функция чистки вырезает первым делом.

**Чистка ответов ИИ.** Модели любят вставлять эмодзи. Защита двухслойная:
в промпте стоит запрет, а `clean_text()` подчищает то, что всё равно
проскочило — осмысленные эмодзи заменяет на наши иконки (`✅`→`✓`, `❌`→`✕`,
`➡️`→`→`), остальные убирает. Замены идут одним проходом регулярки, а не
серией `.replace()`, иначе получается каскад: `💡` меняется на `ℹ︎`, а
следующая замена лезет внутрь только что подставленного символа.

### utils.py
Telegram не принимает сообщения длиннее 4096 символов, а развёрнутый ответ
легко бывает длиннее. Функция `split_text` режет текст на части, стараясь
делать это по границам абзацев, чтобы читалось нормально.

## Полезные детали, на которые стоит обратить внимание

**async/await.** Весь код асинхронный. Пока бот ждёт ответ модели для одного
пользователя (а это секунды), он спокойно обслуживает остальных. Если бы код
был синхронным, все стояли бы в очереди.

**Почему файл называется `openai_provider.py`, а не `openai.py`.** Python при
`import openai` нашёл бы наш файл вместо установленной библиотеки и сломался.
Классическая ловушка новичков.

**Почему у Claude нет `temperature`.** У новых моделей (Opus 4.8) параметры
`temperature` / `top_p` убраны — запрос с ними вернёт ошибку 400. Стиль ответа
теперь настраивается промптом.

**Почему иконки текстовые, а не SVG.** Текст сообщения в Telegram — это plain
text плюс фиксированный набор сущностей (жирный, курсив, код, ссылка, спойлер,
цитата). Ни картинок, ни SVG, ни цвета текста внутри сообщения не существует,
поэтому «красный крестик и зелёная галочка» обычным текстом невозможны.

Единственное исключение — **custom emoji** (премиум-эмодзи), свои картинки
прямо в тексте. По документации Bot API их могут использовать только боты,
купившие юзернейм на Fragment, **либо** боты, чей владелец имеет подписку
Telegram Premium (в личных чатах, группах и супергруппах).

Если Premium появится, путь такой:

1. Рисуешь иконки в SVG, конвертируешь в PNG/WEBP 100×100 (сам SVG Telegram
   не принимает, но как исходник он идеален — контур и цвета сохранятся).
2. Бот загружает их методом `createNewStickerSet` с `sticker_type="custom_emoji"`.
3. Полученные id вписываешь в поле `emoji_id` соответствующих иконок в `icons.py`.
4. Служебные сообщения отправляешь с `parse_mode="HTML"` — метод `Icon.to_html()`
   уже умеет отдавать тег `<tg-emoji emoji-id="...">`.

Код бота при этом не меняется: он и так спрашивает иконку по смыслу.
Осторожно с HTML-разметкой для ответов ИИ — в коде из ответа могут быть
символы `<` и `>`, и сообщение просто не отправится. Для ответов модели
разметку лучше оставить выключенной.

**Почему у Gemini `thinking_level`, а не `thinking_budget`.** У Gemini 2.5
«мышление» отключалось числом (`thinking_budget=0`), а в Gemini 3 параметр
заменили на уровень (`thinking_level=MINIMAL`). Старый параметр на новых
моделях возвращает ошибку 400. Полезный урок: API моделей меняются между
поколениями, и код провайдера привязан к конкретной версии.

**Почему не включена Markdown-разметка.** Модель может выдать текст со
звёздочками и подчёркиваниями, который Telegram не сможет распарсить, и
сообщение вообще не отправится. Поэтому `parse_mode` не задан — всё уходит
обычным текстом, а в промпте есть просьба не использовать разметку.

**Обработка ошибок.** Ожидаемые проблемы (нет ключа, кончился баланс, нет сети)
превращаются в `ProviderError` с понятным текстом и показываются пользователю.
Неожиданные — пишутся в консоль с полным traceback'ом, а пользователь видит
вежливое «попробуй ещё раз».

## Настройки в .env

| Переменная            | Зачем                                              |
|-----------------------|----------------------------------------------------|
| `TELEGRAM_BOT_TOKEN`  | Токен от @BotFather (обязательно)                  |
| `ANTHROPIC_API_KEY`   | Ключ Claude                                        |
| `OPENAI_API_KEY`      | Ключ GPT                                           |
| `GOOGLE_API_KEY`      | Ключ Gemini                                        |
| `DEFAULT_PROVIDER`    | `openai`, `gemini` или `claude` — что при старте   |
| `ANTHROPIC_MODEL`     | По умолчанию `claude-opus-5`                       |
| `OPENAI_MODEL`        | По умолчанию `gpt-4o`                              |
| `GOOGLE_MODEL`        | По умолчанию `gemini-3.6-flash`                    |
| `HISTORY_LIMIT`       | Сколько последних сообщений помнить (по умолч. 20) |
| `REQUEST_TIMEOUT`     | Сколько секунд ждать ответ ИИ (по умолч. 90)       |
| `LOG_LEVEL`           | `INFO` обычно, `DEBUG` при разборе проблем         |
| `CRM_URL`             | Адрес панели управления; пусто — работать без неё  |
| `CRM_BOT_TOKEN`       | Служебный токен панели (её `BOT_API_TOKEN`)        |

Достаточно указать один ключ из трёх — кнопка выбора модели покажет только
доступные варианты. Если провайдер из `DEFAULT_PROVIDER` без ключа, бот
автоматически стартует на том, ключ для которого есть.

## Самопроверка

Перед выкладкой на сервер (и после любой правки кода) стоит прогнать
автотесты — они работают без интернета, реальных ключей и живого бота:

```powershell
py selftest.py          # Linux/сервер: .venv/bin/python selftest.py
```

Проверяются настройки, разрезание длинных ответов, чистка эмодзи, память
диалога и полный прогон переписки через aiogram: команды, кнопки,
вопрос-ответ, поведение при ошибках API и при двух сообщениях подряд.
В конце печатается `Пройдено: N   Провалено: 0` — ноль во второй цифре
означает, что бот собран правильно.

## Если что-то не работает

**`Бот не запущен: Не задан TELEGRAM_BOT_TOKEN`** — нет файла `.env` или он пустой.
Проверь, что файл называется ровно `.env` (Windows любит дописывать `.txt`).

**`TokenValidationError: Token is invalid! It can't contains spaces`** — при
копировании токена в него попал пробел или перенос строки. Токен выглядит как
`8900431873:AAH...` — цифры, двоеточие и 35 символов без пробелов.

**`TelegramUnauthorizedError` / `401 Unauthorized`** — токен неверный или
отозван. Скопируй заново: @BotFather → `/mybots` → бот → **API Token**
(по токену в Telegram можно просто тапнуть — скопируется целиком).
Проверить токен, не запуская бота:

```powershell
.\.venv\Scripts\python.exe -c "import os,httpx;from dotenv import load_dotenv;load_dotenv();print(httpx.get(f'https://api.telegram.org/bot{os.getenv(\"TELEGRAM_BOT_TOKEN\")}/getMe').json())"
```

Должно вернуться `'ok': True` и имя твоего бота.

**`⚠️ Claude: неверный API-ключ`** — ключ скопирован не полностью или отозван.

**`⚠️ ...: нет связи с сервером`** — нет интернета либо API недоступен из твоего
региона. Нужен VPN.

**`⚠️ OpenAI: лимит запросов или закончились средства`** — пополни баланс на
platform.openai.com.

**`python` ничего не запускает / открывается Microsoft Store** — используй `py`
(или активируй `.venv`, внутри него `python` работает нормально).

**Бот не отвечает вообще** — смотри консоль, где запущен `python bot.py`,
там будет ошибка. И проверь, что не запущено две копии бота одновременно:
Telegram не разрешает двум процессам получать обновления одного бота.
