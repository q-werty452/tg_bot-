## Ключи ИИ — как не перепутать

Ключи легко перепутать, они отличаются началом строки:

| Провайдер  | Начало ключа       | Переменная в .env    |
|------------|---------------------|-----------------------|
| Anthropic  | `sk-ant-`           | `ANTHROPIC_API_KEY`   |
| OpenRouter | `sk-or-v1-`         | `OPENROUTER_API_KEY`  |
| OpenAI     | `sk-proj-` / `sk-`  | `OPENAI_API_KEY`      |
| Google     | `AIza`              | `GOOGLE_API_KEY`      |

Ключ показывают **один раз** при создании — сразу копируй.

## Команды Telegram-бота

| Команда   | Что делает                     |
|-----------|----------------------------------|
| `/start`  | Приветствие и краткая справка    |
| `/help`   | Подробно про режимы              |
| `/mode`   | Переключить режим ответа         |
| `/model`  | Переключить Claude / GPT / Gemini |
| `/reset`  | Забыть историю диалога           |
| `/status` | Показать текущие настройки       |
| `/stop`   | Отписаться от рассылок мэрии     |

WhatsApp-бот команд не имеет — там только обычная переписка (WhatsApp Cloud
API не поддерживает команды со слэшем как отдельный UI-элемент).

## Два режима ответа

**▤ Развёрнутый** — полный структурированный ответ: объяснение, примеры,
нюансы. Модели разрешено «подумать» перед ответом. Лимит ответа: 8000 токенов.

**◇ Обсуждение** — короткие реплики на 1–3 предложения, как в обычной
переписке. Лимит ответа урезан до 500 токенов.

Режим — это связка «системный промпт + лимит токенов + настройки модели».
Всё лежит в `prompts.py`, менять характер бота можно там, не трогая логику.
Общий для обоих ботов.

## Что за файлы в проекте

```
tg_bot-/
├── bot.py                       ← точка входа Telegram, вся логика aiogram
├── whatsapp_bot.py               ← точка входа WhatsApp, отдельный процесс
├── conversation.py               ← общее для обоих: запрос к ИИ, восстановление истории
├── logging_setup.py              ← настройка логов (у каждого бота свой файл)
├── config.py                     ← настройки и ключи (.env)
├── prompts.py                    ← тексты промптов для двух режимов
├── storage.py                    ← память бота (кто что выбрал + история)
├── icons.py                      ← набор иконок + чистка эмодзи из ответов ИИ
├── utils.py                      ← мелкие помощники (нарезка длинных текстов)
├── crm.py                        ← клиент REST API панели, общий для обоих ботов
├── remote_config.py              ← настройки, приходящие из панели
├── classify.py                   ← определение темы обращения через ИИ
├── selftest.py                   ← самопроверка: ~190 проверок без ключей и сети
├── providers/                    ← слой работы с ИИ
│   ├── __init__.py               ← фабрика: выдаёт нужного провайдера по имени
│   ├── base.py                   ← общий контракт для всех провайдеров
│   ├── claude.py                 ← реализация для Anthropic
│   ├── openai_provider.py        ← реализация для OpenAI
│   └── gemini.py                 ← реализация для Google
├── requirements.txt              ← список библиотек
├── .env.example                  ← шаблон файла с секретами
└── .env                          ← твои реальные ключи (создаёшь сам, в git не кладём!)
```

Файлы, которые появляются сами и в git не попадают: `bot.log` /
`whatsapp_bot.log` (логи), `crm_queue.jsonl` (недоставленные в панель
обращения), `crm_config_cache.json` / `crm_config_cache_whatsapp.json`
(последняя конфигурация с панели, отдельно на каждый процесс),
`incoming_media/` (фото и документы от жителей, из обоих каналов).

### bot.py / whatsapp_bot.py
Точки входа. У Telegram — `Dispatcher` aiogram, маршрутизирующий сообщения
по `@dp.message(...)`. У WhatsApp — свой `aiohttp`-сервер на `/webhook`
(GET — подтверждение адреса при подключении в Meta, POST — сами сообщения).
Оба вызывают одну и ту же оркестрацию (сессия → панель → ИИ → ответ), но
код специально не обобщён дальше `conversation.py` — детали см. в docstring
`whatsapp_bot.py`.

### conversation.py
`ask_with_fallback()` — спросить модель, при сбое незаметно переспросить
у соседней. `restore_history()` — после перезапуска подтянуть хвост
переписки из панели. Единственное, что реально общее между Telegram и
WhatsApp кодом ответа — остальное завязано на конкретный транспорт.

### config.py
Читает `.env` и складывает всё в один объект `settings`. Проверяет, что
токен Telegram есть и задан хотя бы один ключ ИИ — иначе бот падает с
понятным сообщением при старте. WhatsApp-ключи (`META_*`) не проверяются
здесь — их проверяет сам `whatsapp_bot.py` при старте, раз они нужны
только ему.

### storage.py
Ни Telegram, ни WhatsApp, ни API моделей не хранят состояние — история
переписки хранится в памяти процесса на каждый чат. У каждого бота своё
хранилище (`Storage`), они не пересекаются, даже если оба запущены сразу.
История обрезается до последних N сообщений (`HISTORY_LIMIT`).

**Важно:** хранение в оперативной памяти. Перезапустил бота — всё забылось
(до момента, пока не подтянется история из панели через `restore_history`).
Сессии без активности 12 часов выгружаются автоматически (`Storage.cleanup`).

### providers/
Слой абстракции. Боту всё равно, с кем он разговаривает: он вызывает
`provider.ask(...)` и получает текст.

| | Системный промпт | Роль ответа модели | Где текст ответа |
|---|---|---|---|
| Anthropic | параметр `system` | `assistant` | блоки `content` |
| OpenAI | первое сообщение в `messages` | `assistant` | `choices[0].message.content` |
| Google | `config.system_instruction` | `model` | `response.text` |

### icons.py
Реестр иконок Unicode (`✓ ✕ ⚠︎ ℹ︎ → ▸ ↺ ◎`) — код пишет `ICONS.error`, а не
конкретный символ. Плюс `clean_text()` — чистит эмодзи, которые модель
вставляет вопреки промпту.

### utils.py
`split_text()` режет длинный ответ на куски: Telegram не принимает длиннее
4096 символов, WhatsApp — 4096 тоже. Оба бота используют одну функцию.

### crm.py
Асинхронный HTTP-клиент к панели, общий для обоих ботов. Все методы гасят
сетевые ошибки и возвращают `None` вместо исключения — панель не должна
ломать разговор с жителем. Недоставленные обращения копятся на диске
(`crm_queue.jsonl`) и дошлются, когда панель снова ответит.

## Полезные детали

**async/await.** Весь код асинхронный — пока бот ждёт ответ модели для
одного жителя, он спокойно обслуживает остальных.

**Почему файл называется `openai_provider.py`, а не `openai.py`.** Иначе
`import openai` нашёл бы наш файл вместо установленной библиотеки.

**Почему у Claude нет `temperature`.** У новых моделей (Opus 4.8) параметры
`temperature` / `top_p` убраны — запрос с ними вернёт ошибку 400.

**Почему иконки текстовые, а не картинки.** И Telegram, и WhatsApp принимают
только текст (плюс базовая разметка у Telegram) — цветных иконок внутри
сообщения не бывает ни там, ни там.

**Почему у Gemini `thinking_level`, а не `thinking_budget`.** У Gemini 2.5
«мышление» отключалось числом, в Gemini 3 параметр заменили на уровень.
Старый параметр на новых моделях возвращает ошибку 400.

**Почему не включена Markdown-разметка.** Модель может выдать текст, который
Telegram не распарсит, и сообщение не отправится — поэтому `parse_mode` не
задан, всё уходит обычным текстом.

**Обработка ошибок.** Ожидаемые проблемы (нет ключа, лимит, нет сети)
превращаются в `ProviderError` с понятным текстом для жителя. Неожиданные —
пишутся в лог с traceback'ом, житель видит вежливое «попробуй ещё раз».

## Все настройки в .env

| Переменная               | Зачем                                              |
|---------------------------|----------------------------------------------------|
| `TELEGRAM_BOT_TOKEN`      | Токен от @BotFather (обязательно для bot.py)       |
| `ANTHROPIC_API_KEY`       | Ключ Claude                                        |
| `OPENAI_API_KEY`          | Ключ GPT                                           |
| `GOOGLE_API_KEY`          | Ключ Gemini                                        |
| `DEFAULT_PROVIDER`        | `openai`, `gemini` или `claude` — что при старте   |
| `ANTHROPIC_MODEL`         | По умолчанию `claude-opus-5`                       |
| `OPENAI_MODEL`            | По умолчанию `gpt-4o`                              |
| `GOOGLE_MODEL`            | По умолчанию `gemini-3.6-flash`                    |
| `HISTORY_LIMIT`           | Сколько последних сообщений помнить (по умолч. 20) |
| `REQUEST_TIMEOUT`         | Сколько секунд ждать ответ ИИ (по умолч. 90)       |
| `LOG_LEVEL`               | `INFO` обычно, `DEBUG` при разборе проблем         |
| `OPENROUTER_API_KEY`      | Ключ OpenRouter — шлюза к моделям разных компаний  |
| `OPENROUTER_MODEL`        | Его модель, имя составное: `openai/gpt-4o-mini`    |
| `CRM_URL`                 | Адрес панели; пусто — бот работает без неё         |
| `CRM_BOT_TOKEN`           | Служебный токен панели (её `BOT_API_TOKEN`)        |
| `META_VERIFY_TOKEN`       | Придумываете сами, вписывается и в Meta, и сюда    |
| `META_ACCESS_TOKEN`       | Токен доступа WhatsApp Cloud API                   |
| `META_APP_SECRET`         | App Secret из настроек приложения Meta             |
| `META_PHONE_NUMBER_ID`    | ID номера (не путать с ID аккаунта WhatsApp Business!) |
| `META_GRAPH_API_VERSION`  | По умолчанию `v21.0`                               |
| `WHATSAPP_PORT`           | Порт вебхука whatsapp_bot.py (по умолчанию 8081)   |

Достаточно указать один ключ ИИ из трёх — кнопка выбора модели покажет
только доступные варианты. `META_*` нужны только для `whatsapp_bot.py`,
на `bot.py` не влияют вообще.

## Если что-то не работает

**`Бот не запущен: Не задан TELEGRAM_BOT_TOKEN`** — нет файла `.env` или он
пустой. Проверь, что файл называется ровно `.env`.

**`TokenValidationError: Token is invalid! It can't contains spaces`** — при
копировании токена в него попал пробел или перенос строки.

**`TelegramUnauthorizedError` / `401 Unauthorized`** — токен неверный или
отозван. Скопируй заново: @BotFather → `/mybots` → бот → **API Token**.

**`⚠️ Claude: неверный API-ключ`** — ключ скопирован не полностью или отозван.

**`⚠️ ...: нет связи с сервером`** — нет интернета либо API недоступен из
региона. Нужен VPN.

**`⚠️ OpenAI: лимит запросов или закончились средства`** — пополни баланс на
platform.openai.com.

**WhatsApp: `whatsapp_bot.py` сразу завершается с ошибкой про META_\*** — не
заполнены ключи в `.env`, процесс специально не стартует наполовину
настроенным.

**WhatsApp: Meta присылает 403 на вебхук** — не совпадает `META_APP_SECRET`
(проверка подписи `X-Hub-Signature-256`) или `META_VERIFY_TOKEN` не совпадает
с тем, что вписан в кабинете Meta.

**WhatsApp: сообщения приходят, а ответы не уходят** — почти всегда неверный
`META_PHONE_NUMBER_ID`. В интерфейсе Meta легко перепутать его с ID аккаунта
WhatsApp Business (WABA ID) — это разные числа. Настоящий Phone Number ID
виден в теле любого входящего вебхука, поле `metadata.phone_number_id`.

**Бот не отвечает вообще** — смотри консоль/лог, там будет ошибка. Проверь,
что не запущено две копии одного бота: Telegram не разрешает двум процессам
получать обновления одного токена одновременно.

## Куда развивать дальше

- Сохранять историю в БД, чтобы переживать перезапуск (меняется только `storage.py`).
- Стриминг ответа: показывать текст по мере генерации.
- Голосовые сообщения: распознавание через Whisper (WhatsApp и Telegram оба).
- Свои пресеты промптов: «переводчик», «редактор», «репетитор».
- Ограничение доступа по списку номеров/user_id, чтобы баланс не тратили чужие.
